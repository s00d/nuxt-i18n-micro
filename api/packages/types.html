Locale

Locale configuration object.

Supports arbitrary custom properties via the index signature [key: string]: unknown. To get full TypeScript support for your custom properties, use module augmentation:

// app/i18n.d.ts (or any .d.ts file included in your tsconfig)
declare module '@i18n-micro/types' {
  interface Locale {
    flag?: string
    currency?: string
  }
}

Then access them with full typing:

const locales = $getLocales()
locales[0].flag     // string | undefined  (typed!)
locales[0].currency // string | undefined  (typed!)

interface Locale
code
LocaleCode required
BCP-47 locale code (e.g. 'en', 'de-DE', 'zh-Hans'). Used in URLs and as file/key identifier.
disabled
boolean
When true, this locale is excluded from route generation and language switching.
iso
string
ISO 639-1 / BCP-47 tag for <html lang> and hreflang SEO attributes (e.g. 'en-US').
og
string
Open Graph locale for og:locale / og:locale:alternate meta content (e.g. ar_AE). When omitted, iso is converted to OG format when possible (en-US → en_US). If conversion is not possible, og:locale tags are not emitted (dev warning when missingWarn is enabled).
seo
boolean
Defaulttrue when omitted. · When false, this locale is omitted from cross-locale SEO tags (hreflang, og:locale:alternate). If the configured default locale has seo: false, the x-default hreflang link is not emitted. Routing and translations are unchanged.
dir
'ltr' | 'rtl' | 'auto'
Text direction. Reflected in <html dir> when the locale is active.
displayName
string
Human-readable name shown in language switchers (e.g. 'English', 'Deutsch').
baseUrl
string
Origin of this locale's own domain (e.g. 'https://de.example.com'), plus app.baseURL when the app has one. One build then serves every domain: a request for that host gets this locale, the other locales of the host and the locales with no baseUrl. Links into a locale of another domain ($localePath, $switchLocalePath, the switcher, hreflang) become absolute URLs on its origin, and switching to it navigates there. Any other host gets the build config.
baseDefault
boolean
With baseUrl: this locale is the default of its host, unprefixed there, and links to it from other domains drop /<code>, because the domain already names the locale (https://de.example.com/about, not …/de/about). prefix keeps the prefix in both.
fallbackLocale
string
Locale code to fall back to when a translation key is missing in this locale. Overrides the global fallbackLocale for this specific locale.
[key: string]
unknown

ModuleOptions

interface ModuleOptions
locales
Locale[]
Default[] · List of supported locales. Each entry defines a locale code plus optional metadata (ISO, direction, display name, etc.).
meta
boolean
Defaulttrue · Generate SEO meta tags (hreflang, canonical, og:url, og:locale) automatically.
strategy
Strategies
Default'prefix_except_default' · URL routing strategy for locale prefixes.
  • 'no_prefix' — no locale in URL; locale stored in cookie.
  • 'prefix_except_default' — prefix all locales except the default.
  • 'prefix' — always prefix, including the default locale.
  • 'prefix_and_default' — like prefix, but the default locale is also accessible without prefix.
metaBaseUrl
string
Defaultundefined · Base URL for SEO meta tags (canonical, og:url, hreflang).
  • A concrete URL string (e.g. 'https://example.com') — used as-is (highest priority).
  • undefined — falls back to site.url from nuxt-site-config when that module is present, otherwise the current request origin (useRequestURL().origin on server, window.location.origin on client).
metaTrustForwardedHost
boolean
Defaulttrue · Trust the X-Forwarded-Host header when resolving the base URL for meta tags. Enable when the app runs behind a reverse proxy (nginx, Cloudflare, AWS ALB, etc.) that sets this header to the real client-facing hostname.
metaTrustForwardedProto
boolean
Defaulttrue · Trust the X-Forwarded-Proto header when resolving the protocol for meta tags. Enable when the app runs behind a TLS-terminating proxy so that canonical URLs use https:// even though the app itself listens on HTTP.
trustForwardedHost
boolean
Defaultfalse · Choose the domain of a request (locales[].baseUrl) from X-Forwarded-Host instead of Host. Enable it only behind a proxy that overwrites that header.
hreflangBaseLanguage
boolean
Defaultfalse · Also emit a bare-language hreflang derived from each locale's iso (e.g. es-ES → also es). The first regional locale in locales claims the bare tag for that language. Routing code is never used — only iso || code.
define
boolean
Defaulttrue · Provide $defineI18nRoute() at runtime. The build reads $defineI18nRoute() calls in pages either way.
redirects
boolean
Defaulttrue · Enable automatic locale redirects (server plugin and client route middleware). When true, the prefix strategies redirect an unprefixed URL to its localized form. The locale comes from the app state, the cookie or Accept-Language where autoDetectPath allows, otherwise the default. Under no_prefix detection never changes the URL (see noPrefixRedirect for custom paths).
prefixCaseRedirect
boolean
Defaulttrue · Redirect a locale prefix in another case or encoding to the page in its own spelling (/DE/about → /de/about, /EN/about → /about under prefix_except_default). The router matches the prefix case-insensitively, so without the redirect such a URL would show the page under a second address. When false, or when redirects is false, the URL is a 404. A URL with no page behind it in its own spelling is a 404 either way.
plugin
boolean
Defaulttrue · Register the core i18n plugin that provides $t(), $tc(), $getLocale(), $switchLocale(), and other runtime helpers.
hooks
boolean
Defaulttrue · Call the i18n:register app hook on load and on navigation so plugins can add translations.
components
boolean
Defaulttrue · Register built-in i18n components (<i18n-link>, <i18n-switcher>, <i18n-t>, <i18n-group>). Set to false to disable automatic component registration (e.g. if you don't use them and want to reduce the module footprint).
serverTranslationPreload
boolean
Defaultfalse · Preload index-page translations in Nitro global middleware (server-only, private config).
defaultLocale
string
Default'en' · The locale to use when no locale can be determined from URL or user preferences. It is not a translation fallback: set fallbackLocale for that.
apiBaseUrl
string
Default'_locales' · Base URL path segment for the translations API route (used in SSR/SSG data fetching). Can also be set via NUXT_I18N_APP_BASE_URL environment variable.
apiBaseClientHost
string
Defaultundefined · Override the host used for client-side translation fetch requests. Useful when the client reaches the server via a different hostname than the one Nuxt sees. Can also be set via NUXT_I18N_APP_BASE_CLIENT_HOST environment variable.
apiBaseServerHost
string
Defaultundefined · Override the host used for server-side translation fetch requests. Useful in container/microservice setups where the server reaches itself via an internal hostname. Can also be set via NUXT_I18N_APP_BASE_SERVER_HOST environment variable.
translationDir
string
Default'locales' · Path to the directory containing translation JSON files, relative to the project root.
additionalTranslationDirs
string[]
Default[] · Extra directories whose top-level {locale}.json files are deep-merged into the global dictionary before translationDir. A relative path is read in the project root and in each Nuxt layer root; an absolute path (a Nuxt module's own folder) is read once. Merge order: each entry in array order (across layers), then translationDir (wins on conflicts). Only root {locale}.json files are read — pages/ under these dirs is ignored. Entries other modules add to nuxt.options.i18n.additionalTranslationDirs count, whatever their order. Example: translationDir: 'frontend', additionalTranslationDirs: ['common'] → common/en.json then frontend/en.json.
translationPayloads
TranslationPayloadOptions
Controls how translation payloads are emitted (Node server: public/<apiBaseUrl>; Edge / function / inline: Nitro serverAssets).
  • Node server (node-server, node-cluster, disk serveStatic): serverAssets means local SSR via readFile under public/ (no Rollup raw:).
  • Edge, function presets, and serveStatic: "inline" (vercel, netlify, aws-lambda, winterjs, …): serverAssets registers Nitro serverAssets (assets:i18n), because public/ is not available to SSR on disk. Does not force a public copy — set publicAssets: true for CDN/static. Keep the defaults for the usual all-in-one setup. For large Edge catalogs prefer mode: 'source'. For CDN-backed deployments, disable local outputs and set apiBaseClientHost / apiBaseServerHost.
autoDetectLanguage
boolean
Defaulttrue · Automatically detect the user's preferred language from the Accept-Language HTTP header. Used in combination with autoDetectPath to decide when detection occurs.
autoDetectPath
string
Default'/' · Where cookie / Accept-Language preference redirects may run (when redirects is enabled).
  • '/' — only / (deep links in the default locale stay reachable; default)
  • 'no_prefix' — only paths without a locale prefix
  • '*' — every path, including rewriting an explicit locale prefix (e.g. /fr/about → /de/about when the cookie prefers de)
  • any other string — that path, trailing slashes ignored (e.g. '/welcome')
Under prefix, an unprefixed URL outside the allowed paths still redirects to the default locale's form (/about → /en/about). The default locale with a prefix under prefix_except_default (/en) is a 404, not a redirect.
disableWatcher
boolean
Defaultfalse · Disable the file watcher that auto-creates missing translation files in development mode.
types
boolean
Defaulttrue · Generate TypeScript type declarations for useI18n, $t, and related helpers based on the translation keys in your default locale files.
routesLocaleLinks
{ [key: string]: string; }
Default{} · Map route names to other route names to share the same translation files. For example, { 'about-us': 'about' } means the about-us page will use translations from the about page instead of its own.
plural
PluralFunc
Defaultbuilt-in pluralization (a non-negative integer count picks the form at that index, clamped to the last; negative, fractional and `NaN` counts take the last; `=0 ` opens a template of `Intl.PluralRules` categories) · Custom pluralization function. Receives (key, count, params, locale, getter) and should return the selected plural form as a string, or null/undefined to fall back to the built-in defaultPlural logic (so you can override only some locales). For the Nuxt module the function is serialized with .toString() into .nuxt/i18n.plural.mjs — it must be self-contained (no imports / outer scope). A file path string is not supported.
disablePageLocales
boolean
Defaultfalse · Disable per-page translation files. When true, only global translations ({locale}.json) are loaded; page-specific files (pages/{page}/{locale}.json) are not generated or loaded.
fallbackLocale
string
Defaultundefined (no fallback; returns the raw key) · Global fallback locale code. Keys missing in a locale are taken from this locale (merged into each payload when it is built or loaded); without it a missing key renders as the key itself.
redirectStatusCode
number
Default302 · HTTP status of every redirect the server answers for the module: the preferred locale (cookie, Accept-Language), a prefix in another case, and under hashMode + prefix the move into the hash. 301 and 308 are cached by browsers: a visitor who later changes the preference is still sent where the first answer said. One of 301, 302, 303, 307, 308; any other value warns at build and 302 is used.
linkedMessages
boolean
Defaultfalse · Resolve linked messages (@:key, @.upper:key, @.lower:key, @.capitalize:key, @:{'key'}) in each built dictionary, so the runtime never parses them. A link to a missing key, or a cycle, leaves the message as written and warns at build. Translations added at runtime ($mergeTranslations, i18n:register, inline $defineI18nRoute) are not resolved. Off by default: @: may already be plain text in your messages.
localeCookie
string | null
Defaultnull · Cookie name for persisting the user's locale preference across sessions. Set to null to disable cookie-based persistence. Automatically set to 'user-locale' for the no_prefix strategy if not provided; an explicit null in the i18n config block keeps it off there too.
localeCookieOptions
LocaleCookieOptions
Default{} · Attributes of the locale cookie (and of the hash cookie under hashMode), as the server and the browser write it. Unset fields keep the defaults: path: '/', sameSite: 'lax', a year, no Domain, no Secure. Build config only: no request decides them.
debug
boolean
Defaultfalse · Enable verbose debug logging for locale detection, route generation, and translation loading.
vueDevtools
boolean
Defaulttrue · Register Vue DevTools inspector and timeline in dev (browser extension). Separate from the Nuxt DevTools custom tab.
globalLocaleRoutes
GlobalLocaleRoutes
Default{} · Global route-level locale configuration. Allows restricting or customizing locale routes for specific pages without modifying their components.
  • false — exclude the route from localization.
  • Record<LocaleCode, string> — custom per-locale paths.
customRegexMatcher
string | RegExp
Defaultundefined (uses built-in pattern based on locale codes) · Custom regular expression (or its string source) for matching locale codes in URL segments. Every locale code in locales must match the whole pattern, without its flags, or the build fails.
noPrefixRedirect
boolean
Defaultfalse · For no_prefix strategy: when the default locale has a custom path for a page (localeRoutes / globalLocaleRoutes), redirect the page's original path to the custom path of the visitor's locale, the default locale's otherwise (e.g. /about → /about-us). A locale with no custom path of its own stays on the original path. Pages with dynamic segments are not redirected.
canonicalQueryWhitelist
string[]
Default['page', 'sort', 'filter', 'search', 'q', 'query', 'tag'] · List of query parameter names preserved in canonical and og:url meta tags. Parameters not in this list are stripped from the canonical URL.
trailingSlash
'append' | 'remove'
Defaultundefined (inherit from Nuxt) · Trailing slash for $localePath / $switchLocalePath (NuxtLink parity). Defaults to experimental.defaults.nuxtLink.trailingSlash when unset. Set explicitly to override Nuxt's link default for i18n path helpers.
excludePatterns
(string | RegExp)[]
Defaultundefined · Paths to leave out of i18n routing: a string is a path prefix (/admin covers /admin/x) or a * / ? glob; a RegExp is tested against the path. Matching pages get no locale variants, no locale redirect or 404, and are dropped from prerender; they still render with translations. /api, /_nuxt, /__*, the translations route and common static files (sitemap, robots.txt, favicon, assets by extension) are always excluded.
localizedRouteNamePrefix
string
Default'localized-' · Prefix prepended to localized route names (e.g. 'localized-index'). Used internally to distinguish original routes from generated locale variants.
routeLocales
Record<string, string[]>
Per-route locale restrictions, extracted at build time from $defineI18nRoute() calls. Maps a route path (e.g. '/about') to an array of allowed locale codes. Routes not listed have no restrictions (all locales allowed).
routeDisableMeta
Record<string, boolean | string[]>
Per-route meta tag disabling. Maps a route name or path to true (disable all meta) or an array of locale codes for which meta should be disabled. Entries found in $defineI18nRoute() calls at build time are added to it.
missingWarn
boolean
Defaulttrue · Show console warnings when a translation key is missing (development build, in the browser).
hmr
boolean
Defaulttrue · Enable Hot Module Replacement for translation files in development. When true, changes to JSON translation files trigger an automatic reload without a full page refresh.
cacheMaxSize
number
Default0 · Maximum number of entries in the in-memory translation caches. The fetch and server caches drop the least recently used entry; the browser's dictionary map drops the oldest one (FIFO). 0 means no limit in the browser; server caches keep at most 1000 entries then, so request URLs naming made-up pages cannot grow server memory.
cacheTtl
number
Default0 · Time-to-live (in seconds) of the fetch and server translation caches, counted from when an entry was stored (reads do not extend it), so data from apiBaseServerHost is refreshed at least that often. The browser's active dictionaries are not expired by it. 0 means entries never expire.
cacheStorage
string
Name of a Nitro storage mount (nitro.storage, e.g. 'redis') that several server instances share as a dictionary cache, read after the in-process cache and before the source. Pays off mostly with apiBaseServerHost: one fetch from the backend instead of one per instance. Entries are keyed by build and expire after cacheTtl, or after one day when it is 0. Off in dev and prerender. A failing storage falls back to the source. Unset: no shared cache.
numberFormats
Record<string, Record<string, Intl.NumberFormatOptions>>
Named number formats per locale (Vue I18n-compatible). Enables $tn(1000, 'currency') style calls.
timeZone
string
Defaultthe runtime's zone · IANA time zone for $td and <i18n-t date> (Europe/Berlin). Set it to render one date on the server and in every browser; a named format's own timeZone wins.
datetimeFormats
Record<string, Record<string, Intl.DateTimeFormatOptions>>
Named datetime formats per locale (Vue I18n-compatible datetimeFormats). Enables $td(date, 'short') style calls.
httpCacheDuration
number
Default31536000 · HTTP Cache-Control max-age (seconds) for /{apiBaseUrl}/:page/:locale/data.json. Applies in full only while dateBuild busts the URL (?v=...), which is the default: the response is then private, max-age=…, immutable: a browser pins it, and a CDN that ignores the query cannot (public with httpCacheControl: false).
  • dateBuild: 0/'' — the URL is stable, so this duration is not honoured; the response becomes public, max-age=0, must-revalidate instead. A long max-age on an unchanging URL pins the first payload a browser ever saw.
  • 0 — do not set Cache-Control at all (useful in local debugging)
  • Not applied in development (import.meta.dev) so HMR is not fought by the browser cache
  • Reaches only responses served through Nitro. Payloads copied into public/ and served by the hosting platform take that platform's headers — see the Performance guide. Analogous to @nuxtjs/i18n experimental httpCacheDuration (v10.2.0), but as an explicit response header rather than Nitro defineCachedEventHandler maxAge.
httpCacheControl
string | false
Default'public, max-age=60' · Cache-Control of a payload file answered by a host or by a path-wide rule, which cannot see ?v=. On a Node server a response to the current ?v= is pinned for httpCacheDuration and any other revalidates; with source, cacheTtl or apiBaseServerHost, where a dictionary changes with no build, every response takes this header. false keeps every file on max-age=0, must-revalidate.
dateBuild
string | number
Value used for cache-busting translation requests (?v=...). When not provided, the module uses a hash of the translation files, so the value changes only when translations do (Date.now() when no hash can be computed). 0 or '' turns cache-busting off. Set a stable value (a git SHA, a build number) to pin it yourself. NUXT_I18N_DATE_BUILD or runtimeConfig.public.i18nRuntime.dateBuild replaces it at runtime, after a dictionary was replaced in place: pinned URLs are left behind, with no rebuild.
experimental
Record<string, unknown>
Bucket for experimental/unstable options. Contents may change or be removed without notice between minor versions.

// Assuming keys: 'errors.404', 'errors.500', 'btn.save'
function getErrorText(code: string) {
  return t(`errors.${code}` as ScopedKey<'errors'>)
}

TranslationKey

Resolved translation key type.

  • When DefineLocaleMessage is empty (generator not connected) — resolves to string.
  • When DefineLocaleMessage has keys — resolves to a union of those keys and(string & {}), providing autocompletion while still allowing dynamic keys (plain | string would collapse the union to string).
type TranslationKey = Exclude<keyof DefineLocaleMessage, '__augmentation'> extends never
  ? string
  : Exclude<keyof DefineLocaleMessage, '__augmentation'> | (string & {})

TranslationPayloadOptions

interface TranslationPayloadOptions
mode
'premerged' | 'source'
Default'premerged' · Translation payload strategy.
  • premerged: build-time {page}/{locale}/data.json matrix (default)
  • source: compact source files merged at runtime (prefer on Edge / large catalogs)
serverAssets
boolean
Defaulttrue · Local SSR payloads: a Node server that serves public/ from disk reads that tree (forces public copy); Edge, function presets, and serveStatic: "inline" embed via Nitro serverAssets.
  • Node server (preset serves public/ itself, e.g. node-server): no Nitro serverAssets (avoids Rollup raw:). SSR reads public/<apiBaseUrl|publicDir> as {page}/{locale}/data.json; when this is true, a public copy is forced even if publicAssets is false.
  • Edge, function presets, and inline (nitro.node === false, no disk serveStatic such as vercel / netlify / aws-lambda, or serveStatic: "inline" e.g. winterjs): Nitro serverAssets (assets:i18n) with the same layout as mode. Does not force a public copy — set publicAssets: true for CDN/static.
serverHandler
boolean
Defaulttrue · Register the built-in server route at /{apiBaseUrl}/:page/:locale/data.json. Disable this when translation payloads are served from an external host/CDN.
publicAssets
boolean
Defaulttrue in premerged mode, false in source mode · Copy payloads into Nitro public output. Premerged → {page}/{locale}/data.json under apiBaseUrl; source → compact tree. When SSR reads public/ (node-server and similar), serverAssets: true also forces this copy. On Edge / function / serveStatic: "inline" presets, copy only when this is true (SSR uses the Nitro embed).
prerenderRoutes
boolean
Defaultfalse · Opt in to Nitro-prerender /{apiBaseUrl}/.../data.json. Usually redundant when premerged publicAssets already wrote those files.
publicDir
string
Public output folder relative to Nitro public root. Defaults to apiBaseUrl (_locales). So static files match client fetch URLs (/{apiBaseUrl}/{page}/{locale}/data.json).
rootDelta
boolean
Defaulttrue · Write one root file per locale, and in each page file only what differs from it. The client and SSR merge them; a whole chunk still works wherever a file is read. false keeps a whole dictionary in every page file. premerged only, and off with disablePageLocales.
warnFileCount
number
Default500 · Warn during build when generated payload file count exceeds this threshold.
warnSizeBytes
number
Default10485760 (10 MB) · Warn during build when generated payload total size exceeds this threshold in bytes.
