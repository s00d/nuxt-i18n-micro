mergeTranslationLayers

Two live layers (upper wins) as one tree that answers every key t() answers through them. A null/undefined in upper falls through. Where upper replaces an object or an array of lower, its leaves come back as flat dotted keys (getByPath reads them first), but for the ones upper answers itself.

function mergeTranslationLayers(lower: Tree, upper: Tree): Tree

TranslationHelper

Reads and writes chunks of a TranslationStorage.

Every lookup starts from the Map as it is now, so writes made straight to storage.translations (or by another helper on the same storage) are seen at once.

Stored trees are treated as immutable: a merge copies the nodes on the patch's paths and stores a new root. Trees handed in by callers, returned by t() / getCache, shared between route chunks or cloned storages stay as they were. Replace a chunk instead of editing one in place.

  constructor(storage?: TranslationStorage)
}

Tree

Translation trees: plain JSON objects whose leaves are strings, numbers, arrays, null.

Keys are read the way t() reads them: an own flat key ('a.b': 'x') wins over the dotted walk. __proto__ is never read through or written, so no tree can reach a prototype.
